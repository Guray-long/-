## Design Specificity Verdict

The workflows are product-specific, but the visual language is category-generic Material UI. The detector reported one `flat-type-hierarchy` warning at `index.html:25`; it is a false positive caused by Material icon sizes rather than the text scale. Browser evidence found the stronger problems: clickable product cards are generic non-focusable divs, dialogs lack semantics/focus management/Escape dismissal, icon glyphs pollute accessible names, and state changes are not announced.

## Overall Impression

The app is already responsive, touch-friendly, and grounded in real Thai shop tasks. The biggest opportunity is to make financial actions safer and to turn visual feedback into accessible, recoverable system status.

## What's Working

- Retail task model connects POS, stock, purchases, replenishment, and reports coherently.
- Mobile geometry is strong: no horizontal overflow at 375px and core targets are at least 44px.
- Loading, empty, low-stock, out-of-stock, in-cart, confirmation, and receipt states already exist.

## Priority Issues

1. **[P0] Financially invalid checkout:** cash below total can be submitted and server mutations lack an authoritative session/lock. Fix with inline shortfall validation, authoritative prices, authenticated sessions, and a server lock. Suggested commands: `$impeccable harden`, `$impeccable clarify`.
2. **[P1] Core POS cards are keyboard-inaccessible:** `.product-card` is a clickable div without role/tabindex/keyboard handling. Replace it with a semantic button. Suggested command: `$impeccable audit`.
3. **[P1] Modal accessibility is incomplete:** dialogs lack `role=dialog`, `aria-modal`, labelled titles, focus transfer/trap, Escape dismissal, and focus restoration. Suggested commands: `$impeccable harden`, `$impeccable polish`.
4. **[P1] Hierarchy does not reflect urgency:** dashboard metrics, risks, and analytics use similar card weight; slow-moving products incorrectly offer “เติมสต็อก”. Suggested commands: `$impeccable layout`, `$impeccable clarify`.
5. **[P2] Accessible feedback and brand specificity are thin:** no live regions, Material icon tokens enter names, navigation labels are 10px, and five color themes add customization more than identity. Suggested commands: `$impeccable typeset`, `$impeccable polish`.

## Persona Red Flags

- **Nok, owner-operator during a queue:** cannot immediately tell that cash is short and can commit an invalid sale.
- **Somchai, first-time owner:** technical Apps Script setup language and a raw deployment URL create an onboarding cliff.
- **May, power cashier:** scanner/search exist, but keyboard operation and quick payment shortcuts are missing.

## Minor Observations

- PIN reset is too close to retry.
- Dashboard lacks an explicit date context.
- Several icon-only controls need labels.
- English export/theme labels interrupt the Thai-first register.
- Desktop keeps the mobile bottom-navigation pattern.

## Questions to Consider

- Should selling be the default first screen during business hours?
- Should low stock become an operational queue rather than another dashboard card?
- What product detail would still identify ChowHuay Pro if the theme picker disappeared?
